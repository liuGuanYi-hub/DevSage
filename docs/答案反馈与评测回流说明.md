## 操作背景

答案展示已经具备 Markdown、关键步骤、引用证据和折叠调试信息。为了让检索质量能够持续改进，需要把用户发现的答案问题和错误引用收集起来，并在人工确认后加入评测集。

## 当前流程

1. 前端在答案卡片下提供“答案有帮助”和“需要修正”。
2. 修正反馈可以填写问题说明、勾选错误引用，并填写正确文件路径或行号。
3. `POST /api/feedback` 将反馈保存到 DevSage 自己的 `data/feedback/`，状态为 `pending`。
4. 具备 `writeback_approve` 能力的角色通过 `GET /api/feedback` 查看待确认队列。
5. 人工确认后调用 `POST /api/feedback/{feedback_id}/approve`，服务端把确认结果追加到 `data/feedback/confirmed-evaluation.jsonl`。
6. 评测脚本通过 `evaluation/scripts/dataset_loader.py` 自动加载基础数据集和已确认回流案例。

## 安全边界

- 反馈和确认评测案例只写入 DevSage 的 `data/`，不会修改外部 Obsidian Vault。
- 创建反馈只需要项目 `read` 能力；查看和批准队列需要 `writeback_approve`。
- 批准接口会拒绝重复审核，避免同一个反馈重复进入评测集。
- 评测集回流必须由人工提供参考答案、期望来源和期望工具，系统不会把用户原始答案自动当成标准答案。

## 验证方式

```powershell
python -m pytest backend/tests/test_feedback.py -q
python evaluation/scripts/validate_mvp_dataset.py
```

浏览器验证应确认：提交反馈返回“等待人工确认后进入评测集”，引用复选框保持固定尺寸，Network 中 `/api/feedback` 返回 `200`，且没有浏览器控制台错误。

## 后续扩展

当前回流存储是 DevSage 本地文件实现。正式成员持久化、组织级审核者、审计日志和评测集管理页面仍应在 PostgreSQL 组织模型确定后接入，避免把本地 actor 映射直接当成正式身份系统。
